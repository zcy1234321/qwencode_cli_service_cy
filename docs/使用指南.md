# qwen serve 推理后端使用指南

> 适用项目：`qwencode_cli_service_cy`（qwen serve daemon + Python 薄客户端）
> 读者：要调用这个后端的程序开发者（你自己）

## 0. 一张图看懂

```
你的程序（Python/Node/任意语言）
        │  HTTP + Bearer token
        ▼
  qwen serve  daemon（127.0.0.1:4170）
        │  每个会话一个 ACP 子进程
        ▼
  模型 provider（DashScope / OpenAI 兼容 / Anthropic...）
        +
  工具（读写文件、跑 shell、联网...）+ MCP servers + skills
```

模型 key、MCP、skills、工具权限全部只在 **daemon 一侧**配置；
调用方只需要知道 daemon 地址和 token。

---

## 1. 一次性准备

### 1.1 安装 qwen CLI（已装可跳过）

```bash
npm i -g @qwen-code/qwen-code
qwen --version
```

### 1.2 安装 Python 客户端

```bash
pip install -e .          # 在 qwencode_cli_service_cy 目录下执行
pip install -e ".[ui]"    # 需要 Web 管理界面 / 应用接入网关时（多装 fastapi+uvicorn）
```

### 1.3 配置模型和 API key

编辑 `C:\Users\PC\.qwen\settings.json`（daemon 机器上的全局配置）：

```json
{
  "modelProviders": {
    "openai": [
      {
        "id": "qwen-plus",
        "name": "通义千问 Plus",
        "baseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1",
        "envKey": "DASHSCOPE_API_KEY"
      },
      {
        "id": "my-deepseek",
        "name": "DeepSeek",
        "baseUrl": "https://api.deepseek.com/v1",
        "envKey": "DEEPSEEK_API_KEY"
      }
    ]
  },
  "model": { "name": "qwen-plus" }
}
```

要点：

- **`envKey` 填的是环境变量的名字，不是 key 本身**。key 不落盘。
- 然后在系统环境变量里设 `DASHSCOPE_API_KEY=sk-xxx`（setx 或系统设置）。
  优先级：系统环境变量 > `~/.qwen/.env` 文件 > settings.json 的 `env` 块。
- 想加一个非内置协议的供应商：自定义 id + 顶层 `"providerProtocol": {"myid": "openai"}`。
  注意 `providerProtocol` 改动需要**重启 daemon**。
- 改完 `modelProviders` 后不用重启，调一下热加载：

```bash
curl -X POST -H "Authorization: Bearer %QWEN_SERVER_TOKEN%" http://127.0.0.1:4170/workspace/reload
```

也可以在 daemon 运行时用 API 装 provider（key 由 daemon 代存）：

```bash
curl -X POST -H "Authorization: Bearer %TOKEN%" -H "Content-Type: application/json" ^
  -d "{\"providerId\":\"custom\",\"apiKey\":\"sk-xxx\",\"baseUrl\":\"https://...\"}" ^
  http://127.0.0.1:4170/workspace/auth/provider
```

## 2. 启动 / 停止 daemon

### 2.1 一键演示（没有模型 key 也能跑通全流程）

```powershell
cd <项目目录>\qwencode_cli_service_cy
python scripts\start_demo_stack.py
```

自动拉起三个进程：假模型（回答固定 `fake-answer-N`）+ daemon
（127.0.0.1:4170，token 固定 `demo-token`）+ Web UI（8080）。
看到「演示栈已就绪」后浏览器打开 <http://127.0.0.1:8080>，Ctrl+C 一起停。

### 2.2 真实环境启动（推荐 PowerShell）

整套系统 = daemon（推理后端）+ UI 服务（管理界面 / 应用接入网关），
两个进程，**两个窗口**：

**窗口 1 — daemon：**

```powershell
cd <项目目录>\qwencode_cli_service_cy
qwen_venv\Scripts\Activate.ps1                     # 激活虚拟环境（有的话）
$env:QWEN_SERVER_TOKEN = "自己编的一串长随机字符串"
.\scripts\start-server.ps1                          # 默认 127.0.0.1:4170
```

daemon token 是自己编的密码（不是模型厂商的 apiKey），生成一串：

```powershell
python -c "import secrets; print(secrets.token_urlsafe(24))"
```

**窗口 2 — UI 服务（token 必须和窗口 1 相同）：**

```powershell
cd <项目目录>\qwencode_cli_service_cy
qwen_venv\Scripts\Activate.ps1
$env:QWEN_SERVER_TOKEN = "和窗口 1 完全相同的那串"
$env:QWEN_UI_ADMIN_TOKEN = "另一串管理密码（可选，设了网页会弹窗要一次）"
qwen-serve-ui                                       # 监听 127.0.0.1:8080
```

浏览器打开 <http://localhost:8080>。首次使用到「模型」页装 provider：
选预设 → 填 apiKey → 「获取模型列表」勾选 → 「安装」→「重载配置」。

### 2.3 Windows 常见坑（都是踩过的）

| 报错 | 原因 | 解法 |
|---|---|---|
| `The filename, directory name, or volume label syntax is incorrect` | 在 **cmd** 里写了 `$env:`（PowerShell 语法） | cmd 用 `set QWEN_SERVER_TOKEN=xxx`（等号两边不加引号不留空格），或改用 PowerShell |
| `Activate.ps1 cannot be loaded because running scripts is disabled` | PowerShell 执行策略默认禁脚本 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`（输 Y 确认，只需一次） |
| `start-server.ps1 is not digitally signed` | 项目从 zip 解压，文件带"来自网络"标记，RemoteSigned 下要求签名 | `Get-ChildItem -Recurse .\scripts -Include *.ps1 \| Unblock-File`，或 `Set-ExecutionPolicy -Scope Process Bypass` 只对当前窗口放行 |
| ps1 打开是乱码 / `The string is missing the terminator` | ps1 是 UTF-8 无 BOM，PowerShell 5.1 按 GBK 误读中文注释 | 已修复（文件已加 BOM）；自己新写 ps1 时存成「UTF-8 带 BOM」 |
| 网页「Failed to fetch」 | UI 服务没启动 / 端口不对 | 确认窗口 2 在跑，再刷新页面 |
| 每条消息都要等很久才回 | daemon 的 `session-prompt-settled-close-grace-ms` 默认 0：一轮结束、SSE 一断就拆会话进程，下一条消息冷启动重建 | 该参数需要 **qwen ≥ 0.23.0**（0.21.x 没有这个参数，会报 `Unknown arguments`；升级：`npm i -g @qwen-code/qwen-code@latest`）。`start-server.ps1` 已内置 5 分钟宽限（`-PromptSettledGraceMs`，默认 300000）；手写启动命令时加 `--session-prompt-settled-close-grace-ms 300000` |
| 「已配置模型」404 | qwen 0.21.13 没有 `GET /workspace/models` | 已自动回退读 settings.json，重启 UI 服务即可看到 |

跨机器访问 daemon：`.\scripts\start-server.ps1 -Hostname 0.0.0.0`
（务必设强 token，生产环境加 `--tls-cert/--tls-key`）。

停止：各自窗口 Ctrl+C。需要常驻就配 Windows 任务计划或 pm2。

健康检查：

```bash
curl -H "Authorization: Bearer %QWEN_SERVER_TOKEN%" http://127.0.0.1:4170/health
# {"status":"ok"}
```

## 3. Python 调用

### 3.1 最简单：一问一答

```python
from qwen_serve_client import ask

# token 默认读环境变量 QWEN_SERVER_TOKEN
print(ask("用一句话介绍你自己"))
```

### 3.2 多轮对话（程序内保持上下文）

```python
from qwen_serve_client import QwenServeClient

with QwenServeClient("http://127.0.0.1:4170") as client:
    session = client.create_session(approval_mode="auto")
    sid = session.session_id
    try:
        client.run_turn(sid, "记住数字 42，只回复：已记住")
        result = client.run_turn(sid, "我刚才让你记的数字是？")
        print(result.text)          # 完整文本
        print(result.stop_reason)   # end_turn / max_tokens / cancelled ...
    finally:
        client.close_session(sid)
```

> `scope` 默认 `"thread"`（每次全新会话）。传 `scope="single"` 可 attach 到
> 工作区已有会话。

### 3.3 流式输出

```python
client.run_turn(sid, "写一首短诗", on_text=lambda chunk: print(chunk, end="", flush=True))
```

要更细粒度（工具调用、思考过程、权限请求）用 `on_event`：

```python
def on_event(ev):
    if ev.type == "session_update":
        upd = ev.data.get("update", {})
        if upd.get("sessionUpdate") == "tool_call":
            print("调用工具:", upd.get("title"))
    elif ev.type == "permission_request":
        print("待审批:", ev.data)

client.run_turn(sid, "...", on_event=on_event)
```

### 3.4 异步

```python
import asyncio
from qwen_serve_client import AsyncQwenServeClient

async def main():
    async with AsyncQwenServeClient() as client:
        print(await client.ask("你好"))

asyncio.run(main())
```

### 3.5 指定模型 / 推理力度

```python
# 模型 id 从 GET /workspace/models 查（即 settings.json 里的 id）
session = client.create_session(
    model="qwen-plus",            # → startupConfig.modelServiceId
    reasoning_effort="high",      # none|default|low|medium|high|xhigh|max
)

# 会话中途换模型（HTTP 层）
client._request("POST", f"/session/{sid}/model", json={"modelId": "my-deepseek"})
```

### 3.6 权限模式（无人值守必看）

| approval_mode | 行为 |
|---|---|
| `auto` | 工具自动执行（推荐后端默认值） |
| `auto-edit` | 只自动执行文件编辑类，shell 等仍需审批 |
| `default` | 工具调用产生 `permission_request` 事件，等审批 |
| `plan` | 只出计划不执行 |
| `yolo` | 全部放行（含高危操作） |

```python
session = client.create_session(approval_mode="auto")       # 建会话时定
client.set_approval_mode(sid, "auto-edit")                  # 运行中切换
```

`default` 模式下处理审批：

```python
def on_event(ev):
    if ev.type == "permission_request":
        d = ev.data
        # options 里选第一个（通常是 Allow once）
        client.respond_permission(sid, d["requestId"], d["options"][0]["optionId"])
```

### 3.7 daemon 重启后恢复会话

```python
client.resume_session(sid)      # 磁盘历史还在，模型上下文自动恢复
```

### 3.8 错误处理

```python
from qwen_serve_client import (
    QwenServeError, DaemonHttpError, TurnError, SessionTerminatedError,
)

try:
    client.ask("...")
except DaemonHttpError as e:        # HTTP 层错误
    print(e.status_code, e.code)    # 503 session_limit_exceeded 等
except TurnError as e:              # 模型这一轮失败
    print(e, e.code)
except SessionTerminatedError as e: # 会话死亡/被驱逐
    print(e.event_type, e.data)
except QwenServeError as e:         # 连不上 daemon 等
    print(e)
```

### 3.9 并发

每个任务各开一个 session，互不干扰；同一 session 的多个 prompt 按 FIFO 排队。
并发上限由 daemon 的 `--max-sessions`（默认 32）控制。

### 3.10 嵌入工程化（超时 / 结构化输出 / 会话池 / 附件）

无人值守地把模型推理嵌进程序时，用这些 v0.2 能力（完整示例：
`examples/task_pipeline.py`）：

```python
from qwen_serve_client import (
    QwenServeClient, TurnTimeoutError, JsonOutputError, DaemonHttpError,
)

with QwenServeClient() as client:
    # 1) 超时保护：到期自动 cancel 并抛 TurnTimeoutError，永不挂死
    #    （SSE 默认 90s 读超时，daemon 15s 心跳兜底，死连接自动重连）
    try:
        answer = client.ask("……", turn_timeout=120)
    except TurnTimeoutError as e:
        print("超时", e.prompt_id)

    # 2) 结构化输出：只许 JSON，解析失败自动让模型纠正（同会话追问），
    #    超过 max_attempts 抛 JsonOutputError
    data = client.ask_json(
        "提取收件人和截止时间",
        validator=lambda v: isinstance(v, dict),
        max_attempts=3, turn_timeout=60,
    )

    # 3) 会话池：并发任务复用 session（线程安全）；出错的会话自动废弃
    with client.session_pool(size=4, approval_mode="auto") as pool:
        from concurrent.futures import ThreadPoolExecutor
        with ThreadPoolExecutor(4) as ex:
            results = list(ex.map(lambda t: pool.run(t, turn_timeout=120).text,
                                  tasks))

    # 4) 附件：路径自动上传后随 prompt 发送（≤8 MiB；需 daemon 支持
    #    session_attachments，0.21.x 没有，先 has_feature() 预检）
    r = client.run_turn(sid, "总结这个文件", attachments=["报告.pdf"],
                        turn_timeout=180)
    print(r.usage)   # 本轮上下文占用 {"used": N, "size": M}，可为 None

    # 5) 程序化工具审批：approval_mode="default" 下，on_permission 返回
    #    optionId 即投票，返回 None 留给其它审批方；回调抛异常自动取消请求
    def approve(req):
        if req.tool_name in ("Write", "Edit"):
            return "reject_once"      # 拒绝写文件
        return "proceed_once"
    client.run_turn(sid, "……", on_permission=approve)
```

错误分类：`QwenServeError.transient` / `DaemonHttpError.is_transient` 标记
瞬时故障（连接错误、429/5xx、`session_limit_exceeded` 等），
`DaemonHttpError.retry_after` 携带 daemon 的 Retry-After 秒数。
health/capabilities/会话生命周期请求已内置重试（`max_retries`，客户端构造
参数）；`ask` 整轮重试用 `max_retries` 关键字参数。

## 4. 配置 MCP servers

### 方式 A：配置文件（推荐，持久化）

`C:\Users\PC\.qwen\settings.json`：

```json
{
  "mcpServers": {
    "my-stdio": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:/data"]
    },
    "my-http": {
      "httpUrl": "http://localhost:8000/mcp/",
      "headers": { "Authorization": "Bearer xxx" }
    },
    "my-sse": { "url": "http://localhost:8000/sse" }
  }
}
```

每个 server 还支持：`env`、`cwd`、`timeout`、`trust`、`includeTools`/`excludeTools`
（只暴露部分工具）、`oauth` 等。

热生效：`POST /workspace/reload` 或 `POST /workspace/mcp/reload`。

### 方式 B：CLI

```bash
qwen mcp add my-server npx -y some-mcp-package
qwen mcp list
qwen mcp remove my-server
```

### 方式 C：REST API

```bash
# 增/改（持久化到 settings）
curl -X PUT -H "Authorization: Bearer %TOKEN%" -H "Content-Type: application/json" ^
  -d "{\"scope\":\"user\",\"config\":{\"httpUrl\":\"http://localhost:8000/mcp/\"}}" ^
  http://127.0.0.1:4170/workspace/config/mcp/servers/my-http

# 启停 / 删除 / 重载
curl -X POST .../workspace/config/mcp/my-http/disable
curl -X DELETE ".../workspace/config/mcp/servers/my-http?scope=user"
curl -X POST .../workspace/mcp/reload
```

挂上之后，MCP 工具以 `server名__工具名` 出现在模型的工具列表里，与内置工具同等地位。

## 5. 配置 skills

**就是放目录，不用注册**：

```
C:\Users\PC\.qwen\skills\my-skill\SKILL.md        ← 用户级（所有项目可用）
<项目>\.qwen\skills\my-skill\SKILL.md             ← 项目级（可入 git）
```

SKILL.md 格式：

```markdown
---
name: my-skill
description: 什么时候用这个技能（模型据此决定何时加载）
---

# 具体指令内容……
```

可选 frontmatter 字段：`priority`（数字）、`paths`（glob 门控）、
`user-invocable: false`、`disable-model-invocation: true`。

REST 管理：

```bash
GET  /workspace/config/skills              # 列表

```

## 6. 控制工具（安全边界）

三层机制，按需选用：

| 层级 | 配置 | 效果 | 生效时机 |
|---|---|---|---|
| 禁用 | settings `tools.disabled: ["run_shell_command"]` 或 `POST /workspace/tools/:name/enable {"enabled":false}` | 工具不注册，**模型看不见** | 新 session |
| 拦截 | settings `permissions.deny: ["run_shell_command(*)"]` 或 `POST /workspace/permissions` | 模型可见可调用，执行被拒 | 即时 |
| 审批 | `approvalMode`（会话级） | 谁来拍板：人 / auto / yolo | 即时 |

内置工具全名单（`packages/core/src/tools/tool-names.ts`）：

- 文件/代码：`read_file` `write_file` `edit` `list_directory` `glob` `grep_search` `lsp` `notebook_edit`
- 执行：`run_shell_command` `exec`
- 网络：`web_fetch` `web_search`
- 记忆/技能：`save_memory` `manage_memory` `search_memory` `skill`
- 编排（多代理/定时/工作流）：`agent` `task_*` `team_*` `cron_*` `workflow` `monitor` 等
- 多模态：`image_gen` `omni_*`（按模型能力启用）

无人值守后端的建议收紧配置（settings.json）：

```json
{
  "tools": { "disabled": ["cron_create", "cron_delete", "team_create"] },
  "permissions": {
    "deny": ["run_shell_command(rm -rf *)", "write_file(C:\\Windows\\**)"]
  }
}
```

## 7. 其它语言接入（REST + SSE）

任何语言四步走：

```bash
# 1. 建会话
curl -X POST -H "Authorization: Bearer %TOKEN%" -H "Content-Type: application/json" ^
  -d "{\"sessionScope\":\"thread\",\"approvalMode\":\"auto\"}" ^
  http://127.0.0.1:4170/session
# → {"sessionId":"xxx", ...}

# 2. 发 prompt（202 异步，拿回 lastEventId）
curl -X POST -H "Authorization: Bearer %TOKEN%" -H "Content-Type: application/json" ^
  -d "{\"prompt\":[{\"type\":\"text\",\"text\":\"你好\"}]}" ^
  http://127.0.0.1:4170/session/xxx/prompt
# → {"promptId":"...","lastEventId":N}

# 3. 订阅事件（SSE，Last-Event-ID 保证不重不漏）
curl -N -H "Authorization: Bearer %TOKEN%" -H "Accept: text/event-stream" ^
  -H "Last-Event-ID: N" http://127.0.0.1:4170/session/xxx/events
# 看 type=session_update（文本增量在 data.content.text，
# 其中 data.sessionUpdate="agent_message_chunk"）
# 直到 type=turn_complete（成功）或 turn_error（失败）

# 4. 关会话
curl -X DELETE -H "Authorization: Bearer %TOKEN%" http://127.0.0.1:4170/session/xxx
```

正式客户端可用 qwen-code 仓库的 `docs/developers/daemon-rest-api.openapi.json`
经 openapi-generator 生成。

## 8. Web 管理界面（浏览器里管理 daemon）

不想写代码也能用：项目内置了一个单页 Web 管理界面，把聊天、模型、MCP、
skills、工具开关和 daemon 状态全部集成到一个页面。

```bash
pip install -e ".[ui]"     # 额外装 fastapi + uvicorn
qwen-serve-ui               # 或 python -m qwen_serve_ui
# 参数：--host（默认 127.0.0.1；对外开放用 --host 0.0.0.0，此时务必同时设 QWEN_UI_ADMIN_TOKEN）、--port（默认 8080，可用 QWEN_UI_PORT 覆盖）
```

浏览器打开 http://localhost:8080 。

工作原理：浏览器只连本 UI 服务（FastAPI 代理），UI 服务再用
`QWEN_SERVER_TOKEN` 去调 daemon；**token 只存在服务端，浏览器永远不接触**。
daemon 地址读 `QWEN_SERVE_URL`（默认 `http://127.0.0.1:4170`）。

左侧五个页面：

- **聊天**：会话列表存在浏览器 localStorage，daemon 重启后重新打开会先
  `POST /session/:id/resume` 恢复（失败会提示并可重建）。**刷新页面后
  聊天记录自动恢复**：优先拉 daemon 的 `GET /session/:id/transcript`
  （分页，0.21.13 起支持），旧版无此路由时退化到 UI 服务端的本地缓存
  （`<QWEN_HOME>/ui-chat-cache/<sid>.jsonl`——SSE 事件旁路落盘 + prompt
  时合成的用户消息；删除会话时缓存一并清除）。恢复的消息包含用户/
  assistant 文本、思考和工具调用；历史里的权限审批条只读展示（按钮回调
  早已失效，无法重放）。流式渲染
  assistant 文本/思考/工具调用，权限请求会在消息区弹出黄色审批条；
  「停止」按钮调 `POST /session/:id/cancel`。顶栏可切换模型
  （新会话生效）和 approval mode（当前会话立即生效，
  default / auto-edit / auto / yolo）。侧栏的「📁 工作区」下拉选择
  新会话的工作目录：可选 daemon 默认、已注册工作区，或浏览/输入电脑里
  任意文件夹（数据来自 daemon 的 `/workspace-path-suggestions`）；
  **每个会话独立记住自己的工作区**，会话列表里显示 📁 目录名。未注册过
  的目录由服务端自动调 `POST /workspaces` 注册后再建会话。
  注意 daemon 的两条工作区规则（选择时前端会预检并提示）：祖孙目录不能
  同时是工作区（如 daemon 主工作区在 `...\Desktop\proj`，则 `Desktop`
  及其上级都不能选）；daemon `QWEN_HOME` 下的 `scratch-workspaces` 及其
  整条祖先链（如 `C:\Users`）也不能做工作区。
  侧栏的「🔧 工具」下拉按会话配置工具开关（勾选 = 新会话可用，默认跟随
  工作区全局设置）：daemon 没有会话级工具接口，但工具注册表只在会话创建
  时读一次禁用集，服务端借此临时改工作区级开关、建完立即恢复（期间若有
  并发建会话可能互相影响，管理面单人使用可接受）。自定义过的会话在列表
  里显示 🔧 标记。
- **模型**：已配置模型列表（`GET /workspace/models`）、安装 provider
  （providerId/apiKey/baseUrl/protocol/modelIds）、配置热重载
  （`POST /workspace/reload`）。安装 provider 时可选常用预设
  （OpenAI/DeepSeek/DashScope/Moonshot/智谱/Ollama，自动填 providerId 和
  baseUrl），填好 baseUrl + apiKey 后点「获取模型列表」——UI 服务端代调
  OpenAI 兼容的 `GET {baseUrl}/models`（`POST /api/models/fetch`，避免
  浏览器 CORS），拉回的模型以勾选框展示，勾选即自动填入 modelIds。
- **MCP**：server 列表（启用/禁用/删除）、按 stdio / http / sse 三种类型
  添加或更新（`PUT /workspace/config/mcp/servers/:name`，scope=user）、
  「重载 MCP」让运行中的 daemon 生效。添加方式可切换为「JSON 粘贴」：
  支持 `{"mcpServers": {...}}` 完整配置批量导入多个 server，或粘贴单个
  配置对象（名称取名称框）。
- **Skills**：已安装 skill 列表（启用/禁用/删除）、从本地文件夹安装
  （名称 + daemon 机器上的文件夹路径 + global/workspace 作用域）。
- **工具与状态**：常用内置工具（run_shell_command、write_file、edit 等）
  的启用/禁用开关（**只对新会话生效**），以及 daemon 深度健康状态
  （workspaces/sessions/activeWork 等）和能力清单。

**版本兼容**：UI 会自动探测 daemon 的版本能力（`GET /api/meta` 里的
`mcpPersistentConfig`/`skillsConfigView`/`toolsList`）。以全局安装的
qwen 0.21.5 为例，它比开发版仓库老，差异与回退策略：

- MCP 没有 `/workspace/config/mcp/*` 持久化路由。运行时路由
  `/workspace/mcp/servers` 要求 `X-Qwen-Client-Id` 已在 daemon 注册
  （只有通过会话 attach 的 client 才算），UI 服务用不了，所以增删改
  **回退为直接编辑 settings.json**（`mcpServers` / `mcp.excluded`）再调
  `/workspace/mcp/reload`，持久化生效。注意 UI 服务要与 daemon 看到同一个
  `QWEN_HOME`（默认都是 `~/.qwen`；daemon 若自定义 QWEN_HOME 启动，给
  UI 服务 export 同一个）。
- skills 列表走 `/workspace/skills`（条目是 enabled 布尔而不是 status）；
- **模型列表**：`GET /workspace/models` 在旧版不存在（0.21.13 只有
  DELETE），404 时回退为直接读 settings.json 的 `modelProviders`（provider
  安装本就持久化在那里），前端无感；
- 新版路由 404 时 UI 服务端自动回退旧路由，不需要手动配置。

建议升级 qwen 获得原生持久化路由：`npm i -g @qwen-code/qwen-code@latest`。

注意：UI 服务默认不鉴权——只绑定本机，或设 `QWEN_UI_ADMIN_TOKEN`
（管理面 `/api/*` 需 Bearer，页面会弹窗要一次 token），或加反向代理
鉴权后再暴露到网络。

### 8.1 应用接入网关（多程序分发中转）

有 N 个程序要接同一个 daemon 时，在「🔑 应用接入」页为每个程序建一个
app：独立 token、指定模型、审批模式、工作区目录（`cwd`，留空 = daemon
默认工作区）、工具白名单（`*` / 内置工具名 / `mcp:server名`）、文件路径
白名单、备注，均可随时改、可一键开关。聊天页新建会话时侧栏也可临时指定
工作区（留空 = daemon 默认工作区）。

程序侧不改代码，只把客户端 base_url 指向网关：

```python
from qwen_serve_client import QwenServeClient
# token 用该 app 的 token（创建/重置时完整显示一次）
client = QwenServeClient("http://<网关主机>:8080/app/v1", token="<app-token>")
client.ask("……")   # 其余 API 与直连 daemon 完全一致
```

网关做的事：

- **配置注入**：建会话时强制 profile 的模型、审批模式与工作区目录
  （`cwd`——该程序的会话都在这个目录里读写文件、跑命令；配了白名单的
  app 强制 `default`，因为 `auto`/`yolo` 不产生权限事件，无从拦截）。
  指定的目录若未在 daemon 注册过工作区，网关会先自动调
  `POST /workspaces` 注册再建会话（聊天页手填的工作区同样处理）。
- **执行期拦截**：受限 app 的每个会话由网关后台订阅事件流，对
  `permission_request` 按白名单自动投票——allow 选 allow 系选项，拒绝选
  reject 系（没有 reject 选项则整体取消）。
- **归属隔离**：`/app/v1/session/<sid>/*` 校验 sid 属于当前 token 的
  app，跨 app 访问返回 403。
- **配额**：每 app 可配并发活跃会话上限（`maxSessions`，超限建会话返回
  429 `app_session_quota`；关掉旧会话即释放）和每分钟 prompt 上限
  （`rateLimitRpm`，滑动窗口，超限返回 429 `app_rate_limited` 与
  `Retry-After`）。0 = 不限。
- **多 daemon 路由**：「推理后端」卡片可注册多台 `qwen serve`
  （名称/地址/token，可启停、可探测健康、被引用时禁止删除）。每个 app
  绑定一台（默认 daemon = UI 服务自己的 `QWEN_SERVE_URL`）；请求按
  "会话建在哪台"路由——SSE 事件流和权限投票器也走同一台。注册表存
  `QWEN_HOME/ui-daemons.json`。
- **审计日志**：鉴权失败、会话建/关、prompt（长度 + 前 200 字符预览）、
  权限投票决策（工具、放行/拒绝、原因、命中选项）、配额拒绝、全部管理
  操作，追加落盘 `QWEN_HOME/ui-audit.jsonl`（JSONL，写失败不阻断业务）。
  页面「审计日志」卡片查最近 50 条，或 `GET /api/audit?limit=N`（≤200）。
  路径可用 `QWEN_UI_AUDIT_FILE` 覆盖。
- **开关**：禁用 app 立即拒绝新会话并关闭其存量会话；删除同理。
- **持久化**：app 配置与活跃会话清单存 `QWEN_HOME/ui-apps.json`（原子
  写），UI 重启后自动为存量受限会话恢复投票器。

两个硬性前提：

1. **daemon 绑 127.0.0.1** 且 daemon token 只有网关知道——否则程序可
   绕过网关直连，策略失效。
2. 路径白名单只管得住带路径参数的工具；**shell 命令内的路径无法解析**，
   所以配了路径白名单的 app 必须在工具白名单里显式加 `shell` 才允许
   执行 shell（粗粒度边界，要硬隔离请配合 daemon `--workspace` 与
   沙箱）。

已知边界（当前版本不覆盖）：按 app 的计费（daemon 无用量数据源）、
速率限制为内存态滑动窗口（UI 重启清零，多实例部署不共享）、跨 daemon
无负载均衡策略（app 静态绑定一台）、app token 无过期机制（泄露需手动
重置）。

## 9. 测试与排错

```bash
# 离线单元测试（不需要 daemon）
python -m pytest tests/test_client.py

# 全链路集成测试（自动起假模型 + 独立 daemon，不需要真实 key）
python -m pytest tests/test_integration.py

# 真实 daemon 冒烟（先启动 daemon 再跑）
python scripts/smoke.py
```

常见问题：

| 现象 | 排查 |
|---|---|
| 连接拒绝 | daemon 起了吗？`curl .../health` 通吗？ |
| 401 | token 不一致；daemon 用 `--require-auth` 时 `/health` 也要 token |
| 创建会话 503 `session_limit_exceeded` | 并发满了，调大 `--max-sessions` 或及时 `close_session` |
| 模型没换成功 | 不会报错！看 SSE 的 `model_switch_failed` 事件；modelServiceId 从 `GET /workspace/models` 取 |
| 改了 settings.json 没生效 | 调 `POST /workspace/reload`；`providerProtocol`/`tools.disabled` 要重启或新 session |
| 工具调用卡住不动 | approvalMode 是 default 且没人审批——改 `auto` 或处理 `permission_request` |

## 10. 安全清单（暴露给其它机器前必读）

- [ ] 强 token + `--require-auth`（token 走环境变量，别写进代码）
- [ ] 跨机器时 `--tls-cert/--tls-key` 上 HTTPS
- [ ] `approval_mode` 不要给 `yolo`；优先 `auto`/`auto-edit`
- [ ] `permissions.deny` 挡住高危命令和敏感目录
- [ ] `--workspace` 限定工作目录，别让 agent 满盘跑
- [ ] 模型 key 只在 daemon 机器的环境变量里，客户端只拿 daemon token
